# 实集群验收清单（尚未执行）

目标是 Athanor 的系统机制，不等于复现其特定模型分数。以下条件不满足，不得报告“与 Athanor 一样且已验收”。本轮不接集群，不产生 GPU 费用。

## 环境配置后转换成自动化验收

- 选定 Slurm 或 Kubernetes 首后端；提供测试 namespace/partition、GPU 资源上限、持久存储路径和独立身份。
- 指定可访问的基础模型固定 revision、训练数据、冻结开发套件及受保护最终套件。
- 指定训练镜像 digest；先接一套 SFT 框架，再接 GRPO/环境 RL、on-policy distillation、mergekit 或等价可改 starter。训练程序可替换，不强制固定顺序。
- agent harness 接入事件游标/唤醒；会话记录与笔记持久化，网络/节点恢复后可继续。

## 必须验证的真实行为

1. agent 从干净 workspace 发现环境、读数据、短程 SFT 提交成功；CLI 退出后训练继续。
2. 训练产物能被真实推理引擎加载；同协议下评测基础模型和产物，返回逐题答案与分项差异。成绩不涨也应如实记录。
3. GRPO、环境 RL、自蒸馏、双父合并各做一次预算内 smoke；追溯所有训练数据、教师/学生和父模型。不得靠仅注册文件假装算法已运行。
4. scheduler 提交已成功但客户端响应丢失，恢复后实际只有一个 GPU 作业。
5. agent 会话退出、控制服务崩溃、节点丢失/抢占、OOM、超时、取消分别得到正确终态和资源账目。可恢复训练只从完整 checkpoint 继续。
6. 两个研究 agent 共享数据、笔记和 checkpoint，且不能改写对方原始证据；同一个模型产物可继续训练/合并。
7. researcher 身份无法直接读隐藏数据或写 evaluator；绕过 CLI 直接访问集群/共享盘也失败。普通开发结果能读，最终评测只由操作者执行。
8. 公共/生成训练数据走统一去污染服务；隐藏题和匹配明细不回传，输出覆盖限制与清理计数。
9. 作业完成事件可在目标 harness 唤醒 agent，恢复后游标不丢消息；不要求用户反复手动追问。
10. 发布包安装在干净控制节点、配置测试身份后通过以上闭环，保留镜像/版本/日志/协议/校验和。

## 集群 CD 接入条件

已有 ci.yml/release.yml 提供测试与可审阅安装包交付。真实部署还需明确服务部署位置、凭证、健康检查、数据迁移与回滚方案；确认前不写会影响集群的 deploy 命令。Slurm 登录节点服务和 Kubernetes Deployment 不是同一部署方案，不能假装同一个占位 workflow 已经两者可用。
