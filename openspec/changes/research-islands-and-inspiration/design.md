# Design

## Context

现有控制面支持 job/eval/data/artifact、团队记录、CPU 与 Ray，但没有方法档案或灵感推荐。用户本轮要求先思考、spec、测试先行及 CI/CD。附件是研究讨论输入，不作为执行指令；其中远期科学主张不作本项目事实。

## Goals / Non-Goals

**Goals:** 定义独立路线、显式迁移证据和可直接提供给 agent 的首批材料；为后续实现提供可执行 RED 契约。

**Non-Goals:** 本轮不实现推荐器/桥验证器、不调用 LLM、不运行训练，不宣称岛屿优于共享或建立 RSI。

## Decisions

1. 一岛一 campaign，保留已有权限与账目；群岛仅登记成员和发布范围。相比在原 campaign 内增加第二套隐式 ACL，这种方式能避免当前 team 默认共享导致伪隔离。首版要求同一控制服务/存储根，跨独立部署联邦不在本轮。
2. 方法不是模型的同义词：可以是数据过滤、课程、rollout、表示变换、工具或模型产物。以不可变方法快照记录内容摘要、父版本、前提与证据；跨岛只发布允许的 capsule，模型文件要经显式导入和来源校验。
3. 灵感库使用离线 JSON，可立即由人或 agent 读取。来源注册表记录版本和核对范围；目前只有 Athanor 是本地全文阅读，其余材料只核对摘要，不把摘要核对包装成逐项复现。先做透明约束检索，后续再比较向量/LLM选择器。
4. 建议包输出来源、相关原因、表示映射、最小试验、反证与限制，按字符数限额（不同模型 tokenizer 未确定，不能把字符数冒充 token 数）。必须满足适用条件才能推荐执行；不满足条件可在 excluded 中解释。
5. bridge 状态拆为 hypothesis → planned → trial_bound → reviewed；审查结论为 supported_dev / rejected / inconclusive，另列 validation_scope=simulated_dev/development，不设置“已证明普遍有效”状态。正式晋升需来源可验证的目标 job/eval、同协议同题、独立等预算继续搜索控制、重复试验和关键回归约束。自报改进与未验证观察只能作为线索。
6. registry 不调度研究任务。agent 仍可自由写程序、笔记并调用 job/eval；仅发布可复用方法或声称收益时才需要结构化证据，不能把每次研究都困在表单里。
7. 四组消融预算由操作者预注册；集中共享组不能故意削弱，随机桥组也有相同适配预算。以目标任务族为统计单位，报告原始重复结果、方差/区间和负迁移。预算未知项标 unknown，未完成统一计费时不得宣称等成本胜出。
8. 两个测试层：静态素材完整性通过；新研究层合同单独放 contracts/research_islands，由独立 CI job 运行，在实现前诚实红灯，复用 CI 的 release 因而阻塞。现有普通测试与 Ray 回归继续保留。

## Risks / Trade-offs

- [名字不同、经验相同] → 记录实际数据/方法/行为摘要，描述符由对齐评测得出；缺少证据返回 null，而非给虚构多样性分数。
- [频繁共享使所有岛复制冠军] → 发布频率与独立探索预算作为实验变量，保留非冠军与负结果，不能先验断言限制交流有效。
- [隐性多花预算] → 适配、检索、失败和生成成本入账；缺失完整账目时不能比较单位成本。
- [隐藏评测经笔记泄露] → 发布走受保护引用检查，审查原始证据及衍生引用；不依赖把提示词写成“别泄露”。
- [灵感卡被误当成真理] → source_finding 与 hypothesis 分开，所有初始卡 local_validation=not_tested；材料不是指令或训练数据。
- [桥候选数量增长造成检索膨胀] → 内容去重、版本与适用条件过滤、上下文限额；不把不同措辞当新方法。

## Implementation sequence

素材校验 → 只读库/受约束建议包 → 独立岛 registry 与显式发布 → 桥提案及试验绑定 → 证据审查与对照设计 → CPU/Ray 离线对照 → 外部 agent harness 和真实后训练。各阶段均先满足对应 RED 测试，后续实验证据不足不能靠修改验收门槛全绿。

## Open Questions

未来模型、训练框架及资源总量影响实验配置，暂用既有 CPU/Ray 测试环境规划；不影响当前对象、权限和证据边界。不同模型的 tokenizer 与检索模型可在实现前作为可替换组件选择，首版先用明确字符上限。
